# iPhone BLE 单次运行记录模板

每次运行单独填写并保存完整输出。未知项写“未知”，未执行项写“未执行”；不得由 `passed` 自动补填锁屏、音频或配对确认等人工观察。

## 基本信息

| 字段 | 填写 |
| --- | --- |
| 本次 ID / 对照的归档 ID | 例如新 ID，对照 BZ-HID-04 或 BZ-HID-05/06/07 |
| 开始/结束时间及所在时区 | |
| 操作者 | 可用代号 |
| 源码归档哈希 / 本地修改 | 使用的 archive-manifest 校验结果；修改的文件及原因 |
| 测试目的 | 本轮只验证什么 |
| 输出完整性 | 完整单轮 / 片段；缺失范围 |

## 环境与前提

| 字段 | 填写 |
| --- | --- |
| Linux 发行版、内核、CPU 架构 | |
| Python、Bumble、dbus-fast、BlueZ 版本 | |
| 控制器编号、型号 | 不从 `hciN` 推断型号或适配器数量 |
| iPhone 型号、iOS 版本 | |
| 手机电量、是否连接充电器 | 不据单次失败直接推断因果 |
| 实验入口及模式 | 独占 ancs/hid/cts、BlueZ 共存、HID 退出或无 HID 只读观察 |
| 手机可见名称 | `BT-Auth-*` 或原电脑 Alias |
| 配对前状态 | 电脑记录是否存在、Paired/Bonded/Trusted/Blocked；手机是否保留配对 |
| 本轮前是否重启 | 电脑/手机/都未重启；实际执行时间，未知则注明 |
| 开机及实验期间的相关程序 | 系统蓝牙是否运行；是否有其他 HID、广播或主动连接手机的程序 |
| 初始资源与目标连接 | 注册本轮 HID 前的 HID UUID、广播实例、目标 LE 及加密状态；只读入口记录其起始状态 |
| 与对照轮次的条件变化 | 特别记录 Trusted、配对和地址配置的变化；谁修改、何时修改，未知就写未知 |
| 原有连接及使用情况 | 设备角色、传输类型、是否播放音乐；地址分享时脱敏 |
| 外部认证/锁屏服务的原状态 | 是否为本轮手动暂停；恢复责任 |
| 是否有待恢复记录 | 有则先处理，不能开始新测试 |

## 操作与输出

在这里粘贴**完整实际命令**，包括入口、控制器、模式、配对参数、所有时间和周期参数，以及是否使用自定义状态目录或手机地址来源。

记录手机实际操作：是否锁屏、是否点过设备、是否出现数字确认、是否点击确认、是否有通知授权、是否打开输入框。若中途解锁或点击，写明阶段，不将该轮归为全程无操作。

完整输出文件：填写本次归档位置。运行日志中的密钥文件路径不是需要附送的材料；不要提交 `.runtime` 中的密钥、原 BlueZ 配对库或整个私有目录。

## 结果与判定

| 项目 | 事实或日志字段 |
| --- | --- |
| 名称是否在手机出现 | 人工观察 |
| 链路是否在本次启动后新建 | 开始/后续连接状态；不能把原有连接算作新重连 |
| `connection_setup` | existing / automatic / manual；只读入口未输出则标不适用，并记录开始时是否已有连接 |
| 配对确认及保存 | 人工确认、`bond_saved` 或修复模式证据；区分复用旧配对 |
| 加密及 HID/ANCS/CTS 服务证据 | 原始事件与对应阶段 |
| 周期和实际保持 | 配置值、完成的周期、是否提前结束 |
| HID 退出前基线 | 建连后是否完成 5 秒基线；未到达则注明 |
| 提供进程与服务撤销 | `provider_returncode`、`provider_dbus_closed`、`hid_removed`、`advertising_instances`；只读入口标不适用 |
| 撤销后的连续性 | `same_le_link`、`encrypted`、实际 `observed_seconds`，以及目标断线事件；未连接就超时不能填成保持 60 秒 |
| 原有连接 | 是否中断、是否重新出现；短暂断开也要记录 |
| 音乐/输入体验 | 声音去向、卡顿、断音、屏幕键盘及输入是否正常 |
| `result` 和进程退出码 | 保留原字段，不将 inconclusive 改成 pass |
| 判定 | 通过 / 失败 / 前提不成立 / 观测不足 / 未执行 |
| 支持的结论 | 仅写本轮真正覆盖的范围 |

HID 退出实验要分清“先建立连接再退出”和“退出后才建立连接”；后者不是 BZ-HID-05/07 的已测顺序。`encrypted_hid_read_seen=false` 只表示未观察到重新读取 HID，不等于加密 LE 未建立。不同轮次 Trusted 不同，不能当成只改变 HID 的对照。

## 恢复与后续

| 项目 | 填写 |
| --- | --- |
| 自动或手动恢复命令 | 入口、状态目录、是否重试 |
| `restore` 结果 | 设置、原连接、新增目标连接、广播和 HID/代理清理 |
| 新增观察入口的 `closed` | `active_disconnect_sent`、若有则记录 `cleanup_errors`；HID 退出/只读观察不调用旧入口的 restore |
| 保留的配对/文件 | 与本轮预期是否一致 |
| 目标连接是否按设计保留 | 注销后的连接保持是本项观察结果，不因没有主动断开而判作未清理 |
| 缺失原连接、遗留记录、外部服务 | 尚需处理的具体项，不写笼统“全部清理” |
| 结果变化 | 相比原归档的环境/代码/条件变化 |
| 下一步 | 仅提出能解决具体不确定性的步骤，不默认重复同一失败或追加长测 |
